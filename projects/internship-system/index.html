BUSINESS SYSTEM / OPERATIONS

勤怠・請求書
統合管理システム

総務の実務で見つけた手作業を、Slack・Google Apps Script・Google Sheetsで一つの業務フローへ統合しました。

長期インターンでの実務
担当範囲

成果

公開範囲

  • Google Apps Script
  • JavaScript
  • Slack API
  • Google Sheets

01 / OVERVIEW

現場で経験した手作業を、仕組みから見直す

解決した課題

打刻漏れの確認、稼働・休憩時間の計算、請求書ファイルの作成と命名に手作業が多く、総務担当者の確認・修正負荷が大きい状態でした。

自分の役割

総務業務を自分でも担当して手順を整理し、必要機能の検討から設計、GASでの実装、テスト、導入後の改善まで一貫して担当しました。

期間
2025年8月〜現在
対象
勤怠・請求書処理
連携
Slack / Google Workspace
体制
利用者・上司と連携

公開上の配慮: 雇用契約と守秘義務に配慮し、企業名・実画面・社内データ・内部仕様は掲載していません。

02 / IMPLEMENTATION

業務の流れに合わせて実装した機能

01

Slack打刻

Slackのスタンプ操作から出退勤を記録し、入力の起点を日常の業務ツールへまとめました。

02

稼働・休憩時間の計算

Google Sheets上で稼働時間と休憩時間を自動計算し、定型的な転記と集計を減らしました。

03

手動修正の可視化

人が修正したセルは自動で色を変え、確認が必要な箇所を見つけやすくしました。

04

請求書PDF出力

規定の命名規則に沿った請求書PDFを、1クリックで出力できるようにしました。

05

同時操作への対策

LockServiceで最大30秒の排他制御を行い、同時打刻による競合書き込みを防ぎます。

06

運用・引き継ぎ

設定の外部化と手順の文書化を進め、担当を離れても改善を続けられる状態を目指しました。

03 / FLOW

追加コストを抑えた構成

社内で既に使われていたSlackとGoogle Workspaceを組み合わせ、利用環境・費用・保守性を優先しました。

INPUTSlack打刻操作
→

→

OUTPUTInvoice PDF命名・出力

04 / DECISIONS

利用者と運用を基準にした設計判断

使い慣れた画面を残す

総務担当者が日常的に使うGoogle Sheetsを残し、導入時の学習負荷と手動修正の負担を抑えました。

完全自動化に固執しない

打刻漏れや例外は通知と手動修正で扱い、人が確認できる余地を残しました。

レビューしてから反映する

Pull Requestで上司のコードレビューを受け、本番同等のテスト環境で確認してから本番へ反映しました。

ほかの制作物を見る

個人開発、チームでのデータ分析、ローコード開発の事例も掲載しています。
