SUPERVISED MACHINE LEARNING / OPERATIONS

ML Helpdesk Triage

社内問い合わせを受け付け、カテゴリ・優先度・担当部署を予測する業務支援アプリです。 予測だけで終わらせず、人による確認、履歴、通知、フィードバックまでを一つの流れにまとめました。

01 / OVERVIEW

問い合わせ対応の入口を整える

解決したい課題

問い合わせのたびに担当者が内容を読み、緊急度を判断し、適切な部署へ振り分けると、初動までに時間がかかります。 判断基準が人によって異なると、重要な問い合わせの見落としや担当部署の迷いも生じます。

このプロジェクトの役割

問い合わせ文から三つの項目を一次判定し、信頼度が基準を下回る結果は自動確定せず「要確認」とします。 機械学習を人の判断を置き換えるものではなく、確認すべき対象を整理する手段として設計しました。

03 / FEATURES

主要機能

01

問い合わせの一次判定

自由記述の問い合わせ文からカテゴリ、優先度、担当部署をそれぞれ予測します。

02

信頼度による要確認判定

評価データから決めた基準を下回る予測を、人が確認する対象として分離します。

03

履歴・検索・CSV出力

予測履歴を条件で絞り込み、対応状況の確認や分析用データの出力を行えます。

04

修正フィードバック

誤った予測を修正して記録し、品質条件を満たした場合だけ再学習に利用します。

05

Notion・Slack連携

台帳への自動登録と、中・高優先度の担当部署へのメンション通知に対応します。

06

ログイン・権限管理

社員、担当者、管理者で閲覧範囲と操作権限を分け、管理操作を記録します。

07 / INTEGRATION

Notion・Slack連携

Notion

問い合わせ台帳を自動作成

問い合わせ文、予測結果、確認状態をデータベースへ登録し、業務側の台帳として参照できるようにしました。

Slack

対応が必要な部署へ通知

優先度がMiddleまたはHighのとき、予測した担当部署に対応する担当者をメンションして共通チャンネルへ通知します。

外部APIへの接続情報はコードに含めず、実行環境の環境変数で管理しています。公開デモでは外部連携を無効化します。

08 / AUTHORIZATION

認証・権限管理

社外からの閲覧を防ぎ、役割ごとに必要な機能だけを提供する構成です。

役割主な操作
社員問い合わせ登録、自分の履歴確認
担当者自部署の問い合わせ確認・修正
管理者全履歴、削除、ユーザー管理、監査
  • 管理者が社員アカウントを発行し、自由登録は禁止
  • パスワードはPBKDF2-HMAC-SHA256でハッシュ化
  • 管理操作は実行者・日時・理由を履歴として保存

09 / ENGINEERING DECISIONS

技術的に工夫した点

精度だけでなく誤判定の影響を見る

Accuracyだけで選ばず、クラスごとのF1、Highの見逃し、担当部署の誤振り分けも比較してモデルを選定しました。

低信頼度を自動確定しない

自動振り分けの適合率が校正データ上で90%以上になる基準を探索し、基準未満は人による確認へ回します。

失敗の影響範囲を分ける

Slack通知に失敗しても予測やNotion登録は残し、画面に失敗を明示して再対応できる設計にしました。

修正履歴を学習につなげる

人による修正を記録し、再学習後の評価が既存モデルを下回らない場合だけ更新する品質ゲートを設けました。

10 / BEFORE & AFTER

改善前後の比較

改善前は、問い合わせの判断・記録・通知を担当者が手作業で行います。

業務改善前改善後
一次判断担当者が全文を読み手作業で分類3項目を予測し、要確認だけ人が判断
記録複数の場所へ転記履歴保存とNotion登録を一つの操作で実行
通知担当者を探して個別連絡優先度と部署に応じてSlackへ自動通知
改善誤分類が知見として残りにくい修正フィードバックを再学習候補として蓄積
